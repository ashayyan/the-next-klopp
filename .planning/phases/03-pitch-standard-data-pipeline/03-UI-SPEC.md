# Phase 3 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Scope of this contract.** Phase 3 has two UI surfaces: the `<Pitch>` renderer family (pitch, Canvas layer, glyphs, legend, playback, drag spike), which every later phase consumes, and the dev-only route `/dev/pitch`, which shows all of it. DESIGN.md does not exist yet. Phase 4 picks the final direction and overwrites every colour and font token below. This contract therefore fixes **structure, shape, behaviour, states and copy**, and supplies **neutral, colour-blind-safe placeholder token values** that are already accessible, so nothing in Phase 3 depends on Phase 4.

**Rule for Phase 4 hand-over:** every colour, font and radius used by `src/pitch/**` and `/dev/pitch` comes from a CSS variable declared in one `@theme` / `:root` block in `src/index.css`. No hex value appears in a `.tsx` file. Phase 4 replaces the values, not the code.

Sources used: `03-CONTEXT.md` (locked decisions), `REQUIREMENTS.md` (PITCH-01..04, PIPE-04), `ROADMAP.md` Phase 3 success criteria, `research/pitch-geometry/findings.md` (Law 1 values), `research/interactive-explainers/findings.md` (WCAG 1.4.1 / 1.4.3 rules, Okabe-Ito hex values, stepper-over-autoplay), `research/formations/visual_ideas.md` (arrow-key nudge), `NEW_PROJECT_INPUT.md` §8 and §9.4, `.claude/CLAUDE.md` stack, the dataviz skill (palette validator, mark specs), the web-design-guidelines rules and the taste-skill anti-slop rules.

## Spacing Scale

Declared values (multiples of 4), exposed as `--space-*` and used through Tailwind spacing utilities:

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-label gap inside buttons, legend swatch-to-label gap |
| sm | 8px | Gap between controls in one toolbar group, legend row gap, annotation label padding |
| md | 16px | Page padding below 768px, panel padding, gap between toolbar groups |
| lg | 24px | Page padding 768–1023px, gap between stage and panels when stacked |
| xl | 32px | Page padding at 1024px and up, column gap between stage and side column |
| 2xl | 48px | Space between page header and toolbar at 1024px and up |
| 3xl | 64px | Bottom page padding at 1024px and up |

Exceptions:
- **Touch targets:** every control outside running text (buttons, select, range thumb track, checkboxes with their label) is at least **44 × 44 px**; targets sit at least 8px apart.
- **Draggable player hit area:** an invisible circle of radius **22 px** (screen pixels, converted to metres with the live px-per-metre) behind each draggable glyph, so the target is 44 px even when the disc is 20 px.
- **Glyph geometry** is defined in screen pixels and in metres (see Glyph registry), not in the spacing scale. Legend swatch: 32 × 20 px.
- **Stroke widths** 1.5 px and 2 px (non-scaling) are line weights, not spacing.

## Pitch Contract (PITCH-01)

### Geometry
- `pitchGeometry(length, width)` is pure and returns marking primitives in canonical metres, built from the IFAB 2026/27 Law 1 values in `research/pitch-geometry/findings.md`: halfway line; centre circle r 9.15; centre mark; goal areas 5.5 m deep, 18.32 m wide (7.32 + 2 × 5.5); penalty areas 16.5 m deep, 40.32 m wide; penalty marks 11 m from the goal line; penalty arcs r 9.15 from the mark, drawn **only outside** the penalty area; corner arcs r 1; goals 7.32 m wide.
- Goals are drawn **outside** the goal line, 2 m deep, as a schematic. The 2 m depth is a drawing convention, not a Law value; the geometry function comments say so.
- Centre mark and penalty marks: filled dots, radius 3 px on screen.
- Markings are strokes **centred on the boundary coordinate**, `vector-effect: non-scaling-stroke`, **1.5 px**, `--pitch-line`. Line width is not to scale (the Law's 12 cm line would be under 1 px); geometry stays exact.
- No grass stripes, no gradients, no texture, no drop shadows in Phase 3.

### Coordinates and viewBox
- Canonical space: metres, origin top-left of the field, x along the touchline 0..length, y 0..width downward (locked).
- The SVG user space **is** canonical metres. The outer `viewBox` adds the run-off margin as a view-only concern: `viewBox="-3 -3 {length + 6} {width + 6}"`. Children never offset for the margin.
- Every scene's own `pitch {length, width}` is used. A 100 × 65 m scene draws a 100 × 65 m field with the same 3 m run-off.

### Orientation
- `horizontal` (default): x left→right, y top→bottom.
- `vertical`: a view transform only, rotate −90° so canonical x runs **bottom→top** (a team attacking `ltr` attacks up the screen) and canonical y runs left→right (`view = (y, length − x)`). Data stays canonical.
- Text inside glyphs (numbers, labels) is counter-rotated so it always reads upright.
- The inverse transform used by pointer readout and drag honours the current orientation (tested: a pointer at the screen position of the left penalty mark reads x 11.00 m in both orientations).

### Layer stack (bottom → top)
1. Bottom SVG: run-off rect, field rect.
2. `<CanvasLayer>`: density marks.
3. Top SVG (transparent background): markings → zones → shape connectors → event lines (pass, carry, run, shot) → pressure → players → ball → highlights → annotations and sequence badges → point markers → drag ghost and focus rings.
All three elements are absolutely stacked in one container with identical size and transform. Only the top SVG receives pointer events.

### Sizing
- The pitch fills its column width; height follows the viewBox aspect ratio (no letterboxing, no fixed height).
- The pitch container keeps the default `touch-action` so the page still scrolls on phones; only draggable glyphs set `touch-action: none`.
- Accessible name: the top SVG has `role="img"` with a `<title>` "Pitch, {length} by {width} metres — {scene label}" and a `<desc>` counting what is drawn, e.g. "22 players, 1 ball, 6 passes, 2 carries, 1 shot." When the scene has draggable players the SVG instead has `role="group"` with the same label, so focusable players inside it are reachable.

## Glyph Registry (PITCH-03)

### Glyph sizing rule
Glyph sizes are set in **screen pixels**, converted to metres with the live `pxPerMetre` (from a `ResizeObserver` on the pitch container), and clamped so a glyph stays readable on a phone and does not bloat on a wide screen. Positions are always exact canonical metres. Stroke widths use `vector-effect: non-scaling-stroke`.

| Size | Rule |
|------|------|
| Player disc diameter | `clamp(20px, 2.0 m × pxPerMetre, 28px)` |
| Ball diameter | `clamp(10px, 1.0 m × pxPerMetre, 14px)` |
| Arrowhead | 8 px long, 8 px wide |
| Glyph text | 12 px, weight 600 |

### Glyphs (registry order = legend order)

| # | id | Label (legend) | Description (legend, expanded) | Drawing |
|---|----|----------------|--------------------------------|---------|
| 1 | `player-a` | Team A player — {team name} | Filled disc with shirt number. | Disc filled `--team-a`, 2 px `--pitch-surface` outer ring (separates overlapping discs), number in `--team-a-ink`. |
| 2 | `player-b` | Team B player — {team name} | White disc with a coloured ring and shirt number. | Disc fill `--team-b-fill`, 3 px `--team-b` ring, number in `--team-b-ink`. |
| 3 | `goalkeeper-a` / `goalkeeper-b` | Goalkeeper — {team name} | Rounded square instead of a disc. | Same fill/ring rules as its team; square side = disc diameter, corner radius 4 px. |
| 4 | `ball` | Ball | Small white circle with a dark ring. | Fill `--ball-fill`, 2 px `--ball-ring`. Drawn above players. When a player owns the ball it sits offset 0.6 × disc diameter toward the attacking direction so the number stays readable. |
| 5 | `pass` | Pass | Solid line, arrowhead at the receiver. | 2 px solid, acting-team colour. Arrowhead filled (team A) or hollow with 2 px stroke (team B). |
| 6 | `carry` | Carry | Dashed line: the player runs with the ball. | 2 px, `stroke-dasharray: 6 4`, acting-team colour, same arrowhead rule. |
| 7 | `run` | Run without the ball | Dotted line: movement off the ball. | 2 px, `stroke-dasharray: 0.1 5`, `stroke-linecap: round` (renders dots), acting-team colour, same arrowhead rule. |
| 8 | `shot` | Shot | Heavier line ending in a circle at the target. | 3 px solid, acting-team colour, ends in an 8 px circle: filled = goal, hollow = no goal. Added under Claude's discretion because the Scene `events[]` type list includes `shot`. |
| 9 | `pressure` | Pressure | Wedge from the presser toward the player pressed. | 60° sector, radius = distance to target clamped 2–6 m. Team A: fill team colour at opacity 0.35 + 1.5 px stroke. Team B: no fill, 1.5 px stroke. |
| 10 | `zone` | Zone | Shaded area of the pitch. | Rect or polygon, `--zone-fill` at 0.45, 1.5 px dashed (`4 3`) `--zone-line` border, optional 12 px label top-left on a `--label-bg` chip. |
| 11 | `shape` | Shape line | Line joining players in one unit. | 2 px solid, team colour at opacity 0.6, drawn under players; identity comes from the joined discs. |
| 12 | `highlight` | Highlighted | Dashed ring around a player or point to look at. | 2 px dashed (`4 3`) `--highlight` ring at disc radius + 4 px. |
| 13 | `annotation` | Note | Short label pinned to the pitch. | 12 px ink text on a `--label-bg` chip, 1 px `--label-border`, 4 px padding, radius 2 px; optional 1 px ink leader line to its anchor. Max 40 characters; longer text is truncated with `…` and the full text goes in the `<desc>`. |
| 14 | `point` | Point | A marked spot, such as a tapped answer. | 10 px ink cross (2 px strokes) on a 14 px white circle. Used by quiz-answer scenes and the converter probe. Added under Claude's discretion. |
| 15 | `density` | Event location (Canvas) | One dot per event, drawn on the Canvas layer. | 3 px diameter dots, `--density-mark`. |
| 16 | `sequence-badge` | Sequence order | Number of each action in the possession chain. | 12 px number on a 16 px white circle, 1 px ink ring, placed at each event's start point. |

Rules:
- Every glyph component renders `data-glyph="{id}"` so legend generation and tests can query it.
- A glyph id that is not in the registry is a test failure, not a silent draw.
- Event glyphs follow the playback clock: an event is drawn once `t ≥ event.t`; the event whose time range contains `t` is at opacity 1, earlier events at 0.4. In static (1-frame) scenes all events are at opacity 1.

## Legend Contract (PITCH-03)

- **Auto-generated:** the legend lists exactly the glyph ids present in the current render (including Canvas `density` when that layer is on), in registry order. Team entries use the team names from the scene's `teams[]`.
- **Always visible.** Two states only: **expanded** (swatch + label + description) and **collapsed** (a wrapping icon row: each entry keeps its swatch and its label, descriptions hidden — never swatches alone, so identity is never colour or shape without a word). The legend is never `display:none`, never off-screen, never behind a hover.
- **Placement:** at a container width of 1024 px and up, right column (288 px) beside the pitch, top-aligned with the pitch, `position: sticky; top: 24px`. Below 1024 px, directly under the playback bar (or under the pitch when there is no playback bar), full width, entries in 2 columns at 600 px and up, 1 column below.
- Heading: `h2` "Notation". Toggle: a 44 px button with `aria-expanded` and `aria-controls`, label "Collapse notation" / "Expand notation". Default: expanded at every width.
- Each entry: 32 × 20 px swatch drawn by the registry `sample` (the real glyph component, not an image), 4 px gap, label 14/400 ink, description 14/400 muted.
- The legend is a `<ul>` with one `<li>` per entry; swatches are `aria-hidden="true"` and the label text carries the meaning.
- When no glyph is present, the legend shows "No marks to explain yet." (see Copywriting) instead of an empty list.

## Playback Contract (PITCH-04, PIPE-04)

- Clock: Zustand store `{ t, playing, speed, motion }`, one `requestAnimationFrame` loop advances `t` while `playing`; positions are `f(t)` via `d3-interpolate` between `frames[]`, eased with `d3-ease` `easeLinear` (motion meaning of other easings is Phase 4's).
- **Never autoplays.** Every scene opens paused at `t = 0`. Changing scene resets to paused, `t = 0`.
- Shown only when the scene has 2 or more frames. A 1-frame scene shows the status text "Still scene — 1 frame" in place of the bar.
- Controls, left to right: **Previous frame**, **Play / Pause / Replay**, **Next frame**, **scrubber**, **time readout**, **Speed** select.
  - Previous / Next frame jump to the previous / next entry in `scene.frames` (keyframes, not render frames) and pause.
  - Play at the end of the sequence: playback stops at the last frame (no loop); the button becomes **Replay**, which restarts from `t = 0`.
  - Scrubber: native `<input type="range">`, `min 0`, `max = duration`, `step 0.04` s, label "Sequence time", `aria-valuetext="{t} seconds of {duration}"`. Dragging the scrubber pauses playback.
  - Time readout: mono 14 px, "3.2 s / 12.0 s" (one decimal).
  - Speed: native `<select>` labelled "Speed", options 0.25×, 0.5×, 1× (default 1×).
- **Keyboard** (active while focus is inside the stage region `role="region" aria-label="Pitch stage"`, never page-global):
  - `Space` or `K`: play / pause (native button behaviour when the Play button has focus).
  - `←` / `→`: previous / next frame — **except** when a draggable player has focus, where arrows nudge the player (player wins).
  - `Shift + ←` / `Shift + →`: jump 1 s back / forward.
  - `Home` / `End`: first / last frame.
- Screen-reader announcements (one `aria-live="polite"` region under the bar): on pause "Paused at {t} seconds"; on reaching the end "End of sequence". Nothing is announced per frame.
- **Motion modes** (radio group "Motion"): **Smooth** (interpolated) and **Stepped** (positions jump keyframe to keyframe, holding each for 0.5 s ÷ speed, no interpolation). Default = Stepped when `prefers-reduced-motion: reduce`, otherwise Smooth. The learner-facing default stays user-initiated: nothing moves until Play is pressed in either mode.
- **Reduced motion, UI:** under `prefers-reduced-motion: reduce` all UI transitions are 0 ms. Otherwise UI transitions are `opacity` / `transform` only, 150 ms ease-out, properties listed explicitly (never `transition: all`).
- 60 fps target: the "Stress · 22 players" scene shows a mono readout "Frame time {ms} ms · {fps} fps" (rolling 1 s average) under the bar; no other scene shows it.

## Drag Spike Contract (layer-API consumer 2)

Applies to the `board` fixture (every outfield player of both teams is draggable; goalkeepers and ball are not).

- **Pointer:** `pointerdown` on the 22 px hit circle → `setPointerCapture`; screen → canonical metres through the inverse of the current view transform; position clamped to the viewBox bounds (−3 m … length + 3 m, −3 m … width + 3 m). Cursor `grab` at rest, `grabbing` while dragging. During drag: the dragged player renders on top, a ghost of it stays at the start position at opacity 0.3, `user-select: none` on the page.
- `Escape` during a pointer drag cancels and returns the player to the start position.
- **Keyboard:** each draggable player is a focusable `<g tabindex="0" role="button" aria-roledescription="draggable player">` with `aria-label="{team name}, number {n}, {label}, x {x} metres, y {y} metres"`. Tab order: team A by shirt number, then team B by shirt number. `←↑→↓` nudge 1 m in **screen** directions (so it feels right in vertical orientation too), `Shift + arrow` nudges 5 m; same clamp.
- **Focus ring on the pitch:** two-tone ring so it shows on blue, white and green-grey: 2 px `#FFFFFF` inner + 2 px `--ink` outer at disc radius + 3 px. Visible on `:focus-visible` only.
- **Announcement:** after a drag ends or 500 ms after the last nudge, the live region says "Number {n} moved to x {x} m, y {y} m." (one decimal).
- **Reset:** a "Reset positions" button restores the fixture positions. It is not destructive (no data is persisted in Phase 3) and needs no confirmation.
- Positions in the store are canonical metres rounded to 0.1 m.

The local-only StatsBomb artifact is read through `import.meta.glob` inside the dev-only route chunk, so it can never enter the study or Vercel build; `scripts/check-bundle.ts` remains the enforcing gate.

### Provider landmarks layer
When on, draws the shared landmark fixture (the same JSON used by the TS↔kloppy parity test) converted from **each** provider, as `point` glyphs with a 12 px provider initial chip (S, O, W, T). Correct converters make the four points coincide on every landmark; the left/right asymmetry case is visible as two separate clusters at the two penalty marks.

### Converter probe
Provider `<select>`: "StatsBomb (120 × 80)", "Opta (0–100)", "Wyscout (0–100)", "Tracking (metres, centre origin)". Two `<input type="number">`: "Provider x", "Provider y" (with `inputmode="decimal"`, `autocomplete="off"`). Output (mono 14 px): "Canonical x {x} m · y {y} m". The converted point is drawn as a `point` glyph on the pitch. Out-of-range input shows an inline error under the field in `--danger` and draws nothing.
