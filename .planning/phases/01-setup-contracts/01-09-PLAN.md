<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| PR code to the GitHub Actions runner | workflow code runs with a repository token |
| third-party action to the runner | gitleaks-action executes inside the guards job |
| direct pushes to main | bypass of review and CI |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-35 | Elevation of privilege | ci.yml token scope | high | mitigate | top-level `permissions: contents: read`; plain `pull_request` trigger only (the privileged fork-PR variant is never used); no repository secrets used |
| T-01-36 | Tampering | gitleaks-action supply chain | medium | mitigate | pinned by commit SHA resolved from the v3.0.0 tag; first-party actions on major tags |
| T-01-37 | Tampering | direct push to main | high | mitigate | platform protection if the plan allows; otherwise pre-push hook + PR-only merge rule + CI on every PR, recorded in ADR 0007 |
| T-01-38 | Information disclosure | secrets in history | high | mitigate | gitleaks full-history scan (`fetch-depth: 0`) plus `guard-files.ts --tracked` on every PR; secret scanning recorded as unavailable when the plan lacks it |
| T-01-39 | Information disclosure | token text in docs or PR body | medium | mitigate | only scope names recorded; PR body written from a temp file with no credentials; guard re-run catches secret shapes |
| T-01-SC | Tampering | npm/pip/cargo installs | high | mitigate | CI installs only with `npm ci` from the committed lockfile and runs `npm audit signatures` plus `npm audit --omit=dev --audit-level=high` |
</threat_model>
