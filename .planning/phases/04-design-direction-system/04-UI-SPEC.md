# Phase 4 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Scope of this contract.** Phase 4 has five UI surfaces:

1. Three visual directions (`floodlit`, `programme`, `notebook`), each rendering the same two real screens (a tactics lesson screen and a data lesson screen) under its own token set, in light and dark.
2. The scoring rubric an independent reviewer uses to pick one (ADR 0010).
3. `/dev/gallery`, which shows every primitive and interaction with its states at 375, 768 and 1440.
4. `npm run review:screens`, which captures any route at 3 widths and writes a pass/fail report (QA-02 mechanism).
5. `docs/DESIGN.md` with one fenced `tokens` block, parsed by `scripts/design/build-tokens.ts` into `src/styles/tokens.css`.

No lessons, content engine or app shell beyond what these surfaces need. Structure, behaviour, states and copy below are fixed for all three directions. Only the values in the direction token sets differ, so the comparison is fair. After the pick, the winner's token set becomes the DESIGN.md `tokens` block and the system values in this contract.

**Sources used:** `04-CONTEXT.md` (locked decisions), `REQUIREMENTS.md` (DSGN-01..04, QA-02), `ROADMAP.md` Phase 4, `NEW_PROJECT_INPUT.md` §1, §8 and §9.1–9.8, `03-UI-SPEC.md` (pitch contract, placeholder tokens), `03-UI-REVIEW.md` (open observations), `research/interactive-explainers/*`, `research/learning-science-adhd/*`, `research/how-analysts-watch/visual_ideas.md`, `research/formations/*`, `.claude/CLAUDE.md` stack, `src/index.css`, `src/pitch/**`, the published Wyscout scene `public/data/wyscout/v1-809b8aff1fda/scene-wyscout-2499754-sane-goal.json`, and the skills: design-taste-frontend (palette and type library, layout checker, copy-lint), frontend-design (cliché calibration list), web-design-guidelines, ui-ux-pro-max (pre-delivery checklist), dataviz (validator and mark specs).

**Skill output rejected, with reason:** `ui-ux-pro-max --design-system "interactive sports education learning app data"` returned Claymorphism, indigo `#4F46E5` and Baloo 2 / Comic Neue for children's apps. That is off-brief: the learner is an adult professional, and violet/indigo is banned by the taste skill. Only its pre-delivery checklist is used (no emoji icons, 44 px targets, 4.5:1 text, visible focus, reduced motion, 375/768/1024/1440).

## Spacing Scale

Declared values (multiples of 4), the same in all three directions, exposed as `--space-*`. Tailwind's default 4 px spacing utilities are kept (`p-4` = 16 px), so they map onto this scale.

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-label gap, legend swatch-to-label gap, stat figure-to-label gap |
| sm | 8px | Gap between controls in one group, table cell vertical padding, chip padding |
| md | 16px | Page padding below 768 px, panel padding at 375, gap between regions at 375 |
| lg | 24px | Page padding 768–1023 px, panel padding at 768+, gap between regions at 768 |
| xl | 32px | Page padding at 1024 px and up, column gap at 1440 |
| 2xl | 48px | Sheet padding (`notebook` at 1440), gap between top bar and lesson header at 1440 |
| 3xl | 64px | Bottom page padding at 1024 px and up |

Grid: 4 columns / 16 px gutter at 375, 8 columns / 24 px gutter at 768, 12 columns / 32 px gutter at 1440 with content max-width 1280 px (`floodlit` stage runs full-bleed to 1440 with 32 px padding).

Exceptions:
- **Touch targets:** every control outside running text is at least 44 × 44 px, at least 8 px from the next target (Phase 3 rule, review check `tap-size`).
- **Pitch glyph geometry** is in screen pixels and metres (Phase 3 Glyph sizing rule). One change: player disc minimum rises from 20 px to **22 px** (`clamp(22px, 2.0 m × pxPerMetre, 28px)`) so 12 px numbers fit (03-UI-REVIEW observation).
- **Data marks:** 2 px surface gap between adjacent bars, 2 px lines, 8 px minimum markers (dataviz mark specs) — line weights, not spacing.
- **Rules:** `programme` uses 3 px ink rules; this is a border width, not spacing.

## Typography

Four sizes and two weights, identical in all three directions so the comparison is about faces, not scale. The steps are 14 / 16 / 24 / 36 (fixes the "12/14/16 too close" observation: every step above body is ×1.5).

| Role | Size | Weight | Line Height | Used for |
|------|------|--------|-------------|----------|
| Body | 16px | 400 | 1.5 | Lesson body text (≤ 60 words per step), table cells at 768+, glossary card body |
| Label | 14px | 400 (600 for the active or selected value) | 1.4 | Control labels, legend, step rail, table cells at 375, source line, axis labels, stat labels |
| Heading | 24px | 600 | 1.25 | Step heading (`h2`), panel headings, live shape readout |
| Display | 36px | 600 | 1.1 (`notebook` 1.15) | Lesson title (`h1`) and stat figures; at every width (titles are ≤ 28 characters) |

- **Glyph text** inside the pitch SVG stays 12 px / 600 / 1 (Phase 3 glyph rule). It is glyph geometry, not a fifth type role.
- **Mono** is used only for numbers that change or align: time readouts, coordinates, table numeric columns, stat figures, the shape readout's numerals. Never for labels, eyebrows or headings. Always `font-variant-numeric: tabular-nums`.
- Body measure: 45–70 characters (`max-width: 65ch`).
- No all-caps labels, no letter-spaced eyebrows, no single accented word in a headline (frontend-design calibration list).
- Curly quotes, `…` and `–` (en dash in scores, "5–0") in copy; `−` (U+2212) for negative numbers.

### Font pairings (one per direction, all OFL-1.1, all `@fontsource-variable/*@5.3.0`)

| Direction | Display | Body | Mono | Character |
|-----------|---------|------|------|-----------|

Font budget: ≤ 200 KB WOFF2 in total per direction (Latin subset).

## Motion language

Durations and easings are tokens. Every direction uses the same meaning table; only the values differ.

| Token | `floodlit` | `programme` | `notebook` |
|-------|-----------|-------------|-----------|
| `--duration-ui` | 160ms | 120ms | 200ms |
| `--duration-draw` (arrow, reveal marker) | 240ms | 180ms | 320ms |
| `--duration-morph` (formation change) | 640ms | 420ms | 800ms |
| `--stagger-line` (per line, from the back) | 60ms | 0ms (whole team moves at once) | 80ms |
| `--ease-ui` | `cubic-bezier(0.2, 0, 0, 1)` | `cubic-bezier(0.3, 0, 0, 1)` | `cubic-bezier(0.25, 0.1, 0.25, 1)` |
| `--ease-morph` | `cubic-bezier(0.65, 0, 0.35, 1)` | `cubic-bezier(0.7, 0, 0.3, 1)` | `cubic-bezier(0.45, 0, 0.55, 1)` |

What motion means (all directions):

| Motion | Rule |
|--------|------|
| Player run (off the ball) | Disc moves along its dotted trail with `--ease-morph`; the trail stays at opacity 0.4 after the move. |
| Ball path (pass, shot) | Linear, constant speed, never eased. Ball speed is information. |
| Carry | Player and ball move together, linear. |
| Pressing arrow | Wedge grows from the presser over `--duration-draw`, then holds. Never loops. |
| Formation morph | All outfield players move at once, staggered by line from the back (`--stagger-line`), so each line visibly feeds its digit. Shape lines fade out during the morph and back in after it (`--duration-ui`). |
| Predict → reveal | The answer marker draws in over `--duration-draw`. Correct / incorrect state appears with no shake, bounce or confetti. |
| UI transition | `opacity` and `transform` only, `--duration-ui`, `--ease-ui`, properties listed explicitly (never `transition: all`). Popover and dialog: scale 0.98 → 1 plus fade. |
| Never | Autoplay, loops, parallax, scroll-triggered reveals, elastic or bounce easing, anything moving that the learner did not start. |

Reduced motion (`prefers-reduced-motion: reduce`): all UI durations are 0 ms (existing global rule in CSS stays), the formation morph swaps instantly, playback defaults to Stepped. Motion library: `motion` 14 (`motion/react`) for UI transitions and `useReducedMotion`; pitch movement stays `state = f(t)` on the Phase 3 Zustand clock with `d3-interpolate` and `d3-ease` (ADR 0009).

## Selection rubric (ADR 0010)

The pick is made by a fresh Opus agent that did not build the directions. It receives only: the 36 screenshots (3 directions × 2 screens × 2 themes × 3 widths, default state), the 6 `review:screens` reports, the deuteranopia and achromatopsia captures, `check-palette` output, this rubric, and NEW_PROJECT_INPUT.md §1 and §8.

**Gates (any failure disqualifies a direction before scoring):**
- G1 `check-palette` passes for both themes.
- G2 `review:screens` has 0 FAIL on both screens at 375, 768 and 1440 in the primary theme.
- G3 Both themes render both screens (no missing token, no unstyled element).

**Scored criteria** — each 1–4 with the anchors below; weighted score = Σ (weight × score ÷ 4), out of 100.

| # | Criterion | Weight | 4 (best) | 2 | 1 |
|---|-----------|--------|----------|---|---|
| 1 | ADHD calm and focus | 20 | One focal point per screen at every width; only the CTA and current step use accent; ≤ 60 words in the step; nothing moves unprompted; focus mode leaves only the step | Two or more elements compete; chrome is dense | Busy, noisy, hard to know where to look |
| 2 | Pitch legibility | 20 | At 375 every number readable, no badge/disc/chip overlaps, teams separable in the achromatopsia capture, lines clearly visible, legend adjacent | Readable at 1440 only, or one overlap | Pitch hard to read at any width |
| 3 | Readability at 375 | 15 | Body 16 px at full contrast, measure ≤ 70ch at 1440, no overflow, controls 44 px, table readable without sideways scroll | One squeezed region | Text crowded or truncated |
| 4 | Visual-first | 15 | The visual is the largest element and leads at every width; text supports it | Text leads; visual is secondary | Visual reads as decoration |
| 5 | Anti-slop and taste | 15 | Distinct face and composition; no banned pattern; reads as made for football learning, not a template; taste-skill layout and copy checks clean | Generic but clean | Matches a cliché in the frontend-design list |
| 6 | Colour-blind safety in use | 10 | Deuteranopia and achromatopsia captures keep every team, event and chart distinction | One distinction relies on hue | Identity lost |
| 7 | Premier League feel | 5 | Reads as about the PL: real clubs, season, match, date; football vernacular in layout and type, without crests or logos | Neutral sports look | Not football at all |

Score 3 sits between the 4 and 2 anchors. Tie-break (weighted totals within 3 points): higher pitch legibility, then higher ADHD calm. Parsing and generation rules for `build-tokens.ts` (Node, no tsx; zod 4 schema in `scripts/design/tokens-schema.ts`):
- Input: `--input docs/DESIGN.md` (extracts the single ```` ```tokens ```` block; 0 or 2+ blocks is an error) or a `.tokens.json` file. Output `--out src/styles/tokens.css`. `--scope '[data-direction="floodlit"]'` writes scoped CSS for direction routes. `--check` regenerates in memory and exits 1 with a one-line diff summary if the file differs.
- Required keys: every Phase 3 name in `color` (`surface-page`, `surface-panel`, `surface-raised`, `accent`, `accent-ink`, `danger`, `ink`, `ink-muted`, `control-border`, `focus-ring`) and `pitch` (`pitch-runoff`, `pitch-surface`, `pitch-line`, `team-a`, `team-a-ink`, `team-b`, `team-b-fill`, `team-b-ink`, `ball-fill`, `ball-ring`, `zone-fill`, `zone-fill-opacity`, `zone-line`, `highlight`, `density-mark`, `label-bg`, `label-border`) in **both** themes; `data` `cat-1..3`, `cat-other`, `seq-1..5`, `div-neg`, `div-mid`, `div-pos` in both themes. Colours match `^#[0-9A-F]{6}([0-9A-F]{2})?$`. Aliases `{group.key}` resolve within the same theme; cycles are an error.
- CSS names: `color.*` and `pitch.*` → `--<key>`; `data.*` → `--data-<key>`; `font.*` → `--font-<key>`; `text.*` → `--text-<key>`, `--text-<key>--line-height`, `--text-<key>--font-weight`; `space.*` → `--space-<key>`; `radius.*` → `--radius-<key>`; `shadow.*` → `--shadow-<key>`; `duration.*` → `--duration-<key>`; `easing.*` → `--ease-<key>`; `icon.stroke` → `--icon-stroke`, `--icon-linecap`.
- Theme output: light values under `:root` (or the scope); dark under `[data-theme="dark"]` and under `@media (prefers-color-scheme: dark) { :root:where(:not([data-theme="light"])) }`. `@font-face` rules from `font.*.$extensions.tnk.files` with `font-display: swap`. A `@theme inline` block maps `--color-<key>: var(--<key>)` for `color.*` and `--color-data-<key>` for `data.*`, plus `--font-*`, `--text-*`, `--radius-*`.
- `src/index.css` keeps `@import "tailwindcss";`, imports `./styles/tokens.css`, and keeps the reduced-motion and drag focus-ring rules; its placeholder `:root` block is deleted.
- Theme toggle: `localStorage` key `tnk:theme` (`system | light | dark`), read and written inside try/catch; an inline script in `index.html` sets `data-theme` before first paint so there is no flash.
