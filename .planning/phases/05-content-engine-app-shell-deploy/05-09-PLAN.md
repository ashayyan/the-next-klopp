**As a** learner, **I want to** have lessons authored as validated data that render in a navigable app protected on Vercel, **so that** every shipped lesson is traceable, tested, never public and never broken.

<objective>
Build the claim components that make every fact visibly sourced: chips with a registry popover, the step source line, the rule card with its dates, the contested panel, numbers that bind to pipeline outputs, and the scene still for visuals; then use all of them in the fixture lesson.

Implements CONTEXT "Claim components (CONT-05)" (`<Fact source>`, `<Stat source | data value unit>`, `<Rule source law>` with effective and as-of dates, `<Contested sides>` with at least two sourced sides, a visible chip that opens the registry entry, never silent), UI-SPEC "Claim components and source chips", "Source line", "Motion" (popover), UI Considerations rows "Source chip", "Rule card" (populated and Recheck due), "Contested", "Data-bound stat" loading and error. RESEARCH Pattern 7 (claim ids), Pitfall 1 (`data-claim-meta`), Pitfall 2.

Planner decisions: a data-bound `<Stat>` cites its dataset as its own source-line item ("Data: {dataset} {version}. Licence: {licence name}.") and its chip uses that item's number; `<Visual scene="<dataset>/<version>/<file>" at="end">` renders a static pitch of the scene with its legend, so lesson files never import a scene.

Purpose: CONT-05, every claim a learner reads shows where it came from.
Output: nine MDX components, the source line, the data loader, the citations export, the fixture with every claim type, walker chip checks.
</objective>

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-05-30 | Tampering | external source links | medium | mitigate | links come only from registry `url` (validated `httpUrl`), open with `rel="noopener noreferrer"`; lesson links are limited by `link-scheme` (05-03) |
| T-05-31 | Tampering | data fetches | low | mitigate | only refs matching the data-ref pattern are fetched, always under `/data/`; content type must be JSON; the scene is schema-validated before drawing |
| T-05-32 | Repudiation | silent claims | medium | mitigate | every claim renders a chip; an unresolved id shows "Source missing" in dev and the validator blocks shipping it |
| T-05-SC | Tampering | npm installs | high | accept | no package installed here |
</threat_model>
