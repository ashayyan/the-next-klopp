**As a** learner, **I want to** have lessons authored as validated data that render in a navigable app protected on Vercel, **so that** every shipped lesson is traceable, tested, never public and never broken.

<objective>
Freeze the three content contracts of the phase (lesson spec v1, verification record, What's new) as JSON Schema plus Zod mirrors, make the build reject a malformed lesson, and give the app every curriculum fact it needs through the one virtual module.

Implements CONTEXT "Spec schema source of truth" (JSON Schema frozen v1 plus Zod mirror plus parity test; reversibility costly), "What does the spec hold?", "Lesson Loop stages", "Verification record format" (schema only; the rules come in 05-13), "What's new source", post-research decision "Chapter ids are part-a, part-b… from the concept-map part field", and UI-SPEC "Track titles and numbers come from TRACKS … moved or re-exported to a shared module the app can import". RESEARCH Pattern 3.

Planner decisions (cheap to change, recorded in ADR 0011):
- `steps[].screen` is optional and names the MDX `<Step>` anchor; it defaults to `id`, so the CONTEXT rule "each `<Step>` id matches a `steps[].id` in order" holds for every lesson that omits it.
- `durationMin` is an integer 1–60 in the schema; the friendly 5–12 rule is the validator's `duration` rule (05-06), so authors get a plain-English message.
- Verification claims carry `sourceId` always and `dataRef` for data-bound stats; `url` is an http(s) URL or a root-relative `/data/` path.

Purpose: every rule, component and gate after this reads one frozen shape.
Output: three schemas, fixtures, Zod mirrors, curriculum builders, the seed What's new file, ADR 0011.
</objective>
