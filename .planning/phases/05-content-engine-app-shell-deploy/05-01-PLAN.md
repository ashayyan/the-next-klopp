**As a** learner, **I want to** have lessons authored as validated data that render in a navigable app protected on Vercel, **so that** every shipped lesson is traceable, tested, never public and never broken.

<objective>
Prove the content architecture end to end before anything else is built on it: one fixture lesson written as `lesson.mdx` plus `lesson.json` is picked up by a build-time virtual module, compiled by MDX, and rendered at `/learn/:lessonId`, and the same mechanism keeps fixtures and drafts out of the study build.

Implements CONTEXT "Lesson file format and layout" (folder layout, `<Step id>` wrapper, components through `MDXProvider`, no imports in lesson files), "Draft visibility" (build-time filter; fixtures only with `VITE_INCLUDE_FIXTURES=1`), post-research decisions "Lessons carry no frontmatter … `remark-mdx-frontmatter` not installed" and "Drafts and fixtures are excluded from bundles by a Vite virtual-module plugin (not a runtime filter) … Walker build goes to `dist-walker/`", and "Decided autonomously: Tooling" (exact pins through the Phase 4 legitimacy gate). New, `scripts/lib/content/select.ts` (pure, erasable TypeScript, no Vite import):
- `type SelectMode = { command: "serve" | "build"; includeFixtures: boolean; test: boolean }`
- `selectLessons(all: { spec: { id: string; status: string }; fixture: boolean }[], mode: SelectMode)` returns the included subset:
  - `test` true (vitest, Vite `mode === "test"`): every lesson and every fixture.
  - `command === "serve"`: every non-fixture lesson of any status; fixtures only when `includeFixtures`.
  - `command === "build"` with `includeFixtures`: lessons with status `shipped` or `shippable`, plus every fixture.
  - any other build (study and Vercel): status `shipped` only, never a fixture.
- Discovery (in the plugin, not select.ts): `content/tracks/<track>/<chapter>/<lesson>/lesson.json` and `content/_fixtures/<lesson>/lesson.json`; the folder `content/_fixtures/invalid/` is never discovered (validator test material from 05-03).
