**As a** learner, **I want to** have lessons authored as validated data that render in a navigable app protected on Vercel, **so that** every shipped lesson is traceable, tested, never public and never broken.

<objective>
Make every fact in a lesson traceable: claims resolve to the source registry, regulations carry their effective and as-of dates, data refs resolve to published, licence-clean artifacts, and no bare number slips into prose without a source.

Implements CONTEXT rules `citation`, `data-ref`, `bare-number` (with the `<Num kind>` closed list), "Rule … validator fails a <Rule> whose source lacks effective_date/as_of", "Registry shape gaps? → add optional effective_date … additively", post-research decisions "as_of already exists … only effective_date is added, through the domain sources.json files and the build-registry.ts merge so build-registry --check stays green" and "'Law 10' style references stay inside <Rule> children; the <Num kind> list is not widened". RESEARCH Patterns 4 and 7 (claim ids), Pitfall 6.

Planner decision: `source-unlisted` keeps `sources[]` the complete list the source line and chip numbering read from (05-09).

<assumption_delta_decision>
Noun that stays primary: the registry source entry (`id`). Decision: add-alongside — `effective_date` (when a rule starts to apply) is a different fact from `as_of` (when the entry was last checked), not a generalisation of it, so both live side by side; nothing forces a later promote.
</assumption_delta_decision>

Purpose: CONT-02 citation, data-ref and bare-number breaks and the CONT-05 regulation dates are enforced before claim components ship.
Output: additive registry field, claim extractor, five rules, nine fixture folders.
</objective>
